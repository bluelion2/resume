경력기술서 — 강승훈

8년차 프론트엔드 개발자입니다. 레거시나 초기 단계의 서비스를 넘겨받아, 서비스를 멈추지 않고 점진적으로 개선하는 일에 강점이 있습니다. 논의된 내용과 히스토리를 기록하고 구조화해서, 팀이 같은 고민을 반복하지 않도록 만드는 것을 좋아합니다.

핵심 역량

역량 대표 사례
레거시의 점진적 전환 3년간 방치된 CMS를 iframe 공존 방식으로 페이지 단위 교체 · Redux/MobX 혼용 상태관리 일원화 · 외주 개발 사이트 인계 후 개선

사장님을 위한 서비스 "캐시노트"의 웹뷰 서비스를 개발합니다. 그중 사장님들이 물품을 싸게 구매하는 마켓 서비스를 담당하고 있습니다.

Stack · Next.js, TypeScript, React Query, Tailwind CSS, Datadog

마켓플레이스 팀 (2023.04 ~ 2024.10, 2025.06 ~ )

캐시노트 앱 안의 커머스 서비스(구매자)와, 입점사·내부직원용 어드민을 함께 개발합니다. 일매출 200만원 수준이던 서비스가 일매출 평균 1억 3천만원까지 성장하는 동안 FE를 담당했습니다. 처음에는 혼자 FE를 맡았고, 거래액이 늘면서 충원된 FE 2명과 함께 진행했습니다.

홈 초기 로딩 성능 개선

  • 배경: 서비스를 고도화하면서 홈에 기능이 계속 붙었고, 초기 로딩이 눈에 띄게 느려졌습니다.
  • 해결
    • chunk size를 줄이고, 첫 화면 아래(BTF) 영역은 레이지 로딩했습니다.
    • API Prefetch로 필요한 데이터를 미리 캐싱했습니다.
    • 이미지 리사이징을 적용했습니다.
  • 결과: LCP 3.4s → 최대 1.4s

결제 수단 확장

  • 배경: 초기에는 카드결제만 지원했습니다. 서비스가 점점 커지고 사용자 수가 늘어나면서 다양한 결제수단 지원이 필요해졌습니다.
  • 해결
    • 포인트, 무통장 입금, 간편결제(네이버페이)를 추가했습니다.
    • 이 과정에서 PG사가 바뀌어 결제 구조 개선도 함께 진행했습니다.

프로모션 페이지 모듈 시스템

  • 배경: 프로모션 페이지 제작 요청이 주 1회 이상 들어왔고, 그때마다 개발자가 반복해서 작업하고 있었습니다.
  • 해결: 모듈 시스템을 제안하고 설계·구현했습니다. 개발자 도움 없이 마케터가 어드민에서 프로모션 페이지(또는 페이지 안의 영역)를 직접 조합할 수 있습니다.

입점사·어드민 백오피스

  • 매출이 늘면서 입점사가 주문·배송·정산을 직접 처리할 수 있도록 기능을 고도화했습니다.
    • 정산, 상품, 주문, 배송, CS 문의
    • 엑셀 업로드·다운로드로 대량 작업 처리
    • 거래명세서, 발주서, 정산 테이블 PDF 생성

서비스 안정성

  • Datadog RUM·APM으로 모니터링 환경을 구축했습니다.
  • E2E 테스트를 구축했습니다.

광고 팀 (2024.10 ~ 2025.05)

체험단 서비스(현 캐시노트 플레이스)의 어드민을 개선했습니다. 이후 노란우산공제, 대출 중개, 사업자 신용카드 판매 같은 금융중개 서비스가 추가되면서 유지보수까지 맡았습니다. 백엔드 개발자 1명과 함께 진행했습니다.

홈택스 스크래핑 기반 비동기 신청 flow 설계

  • 배경
    • 기존에는 스크래핑 없이 대략적인 금액만 보여 주고 있었습니다.
    • 그래서 예상 대출 금액과 실제 금융사에서 받을 수 있는 금액의 차이가 컸고, 대출 신청률이 저조했습니다.
    • 정확한 금액을 보여 주려면 홈택스 스크래핑 정보가 필요했습니다. 스크래핑은 앱에서 요청해야 하고, 결과도 비동기로 돌아왔습니다.
  • 해결: 앱에 스크래핑을 요청하고, 성공·실패에 따라 분기하는 비동기 처리 flow를 설계하고 구현했습니다.

사업자 신용카드 한도조회 서비스

  • 현대카드 사업자 전용 신용카드를 발급받기 전, 사장님의 홈택스 정보로 예상 한도를 조회하는 서비스를 개발했습니다. 조회 후 바로 발급 신청까지 이어집니다.

FE 협의체 (2023.10 ~ )

사내 FE 개발 환경의 표준화와 생산성 향상을 위한 가상 조직입니다. FE 전반의 이슈와 주요 논의사항을 책임지고 결정하며, 결정 사항과 사라지기 쉬운 논의 내용을 문서로 남깁니다.

주요 의사결정

결정 배경 결과
Datadog 로그 수집 공통 라이브러리 팀별로 로그 수집 방식과 수집률이 제각각이었음 공통 라이브러리로 수집 방식과 수집률을 통일
모노레포 → 멀티레포 분리 서비스 고도화와 인력 충원으로 목적조직별 독립 관리가 필요했음 서비스별로 독립적으로 관리하기 쉬워짐
디자인시스템 범위를 컴포넌트 → Foundation(font size, color 등)으로 축소 AI 활용으로 코드 생산 속도가 빨라지면서 피그마와 디자인시스템 코드의 차이가 커짐 유지보수 비용 감소, 더 빠른 개발 가능

공통 자산 관리

  • 디자인 시스템, 이벤트 로그 수집, 웹뷰–앱 통신 인터페이스 같은 공통 라이브러리를 관리합니다.
  • 회사 홈페이지처럼 담당이 불분명한 서비스도 맡고 있습니다.
  • 신규 입사자 온보딩 가이드와 기술 표준 가이드를 작성했습니다.
  • 서비스·어드민용 저장소 템플릿과 공통 배포 프로세스를 마련했습니다.

프리윌린 (2019.08 ~ 2023.03)

학원용 수학 학습 구독 서비스 "매쓰플랫"의 웹 버전을 개발했습니다. 학습지 만들기, 채점 및 보고서 생성 같은 핵심 기능과, 출석·학원비·학생 관리 같은 학원 운영 기능이 있습니다.

Stack · React, TypeScript, MobX, Emotion

수학문제 CMS 개발 (2022.11 ~ 2023.03)

수학문제, 교재, 학습지를 관리하는 내부 CMS를 새로 만드는 프로젝트입니다. 3년 전에 만들어진 뒤로 유지보수가 거의 안 된 상태였고, 신규 기능 요청이 들어오면서 새로 만들기로 했습니다. 프론트엔드 기술 환경 구성부터 맡았습니다.

서비스를 멈추지 않는 점진적 전환

  • 배경
    • 많은 내부 직원이 매일 쓰는 서비스라 한 번에 바꿀 수 없었습니다.
    • 기존 코드를 리팩토링하는 것보다 새로 띄우는 편이 전체 일정이 짧다고 판단했습니다.
  • 해결
    • 신규 프로젝트와 기존 프로젝트를 iframe으로 연결했습니다.
    • 양쪽의 인증을 함께 처리했습니다.
    • 기존 페이지는 그대로 쓰면서 신규 페이지로 하나씩 교체했습니다.

수학기호 처리 공통 모듈

  • 배경: 수학기호 렌더링이 특정 라이브러리에 깊게 의존하고 있었습니다. 마이너 버전만 바뀌어도 여러 곳에서 에러가 났습니다.
  • 해결
    • 주관식, 객관식, 서술형 등 여러 답안 상태와 수학기호 처리를 하나의 공통 모듈로 모았습니다.
    • UI에서는 이 모듈로만 수학기호를 쓰도록 강제했습니다.
  • 결과: 이슈가 생기면 모듈만 고치면 전체가 대응됩니다. 라이브러리를 바꾸더라도 UI 로직은 영향을 받지 않는 구조를 만들었습니다.

매쓰플랫 서비스 개발 (2019.08 ~ 2023.03)

안드로이드 태블릿 앱 "매쓰플랫"과 같은 기능을 웹에서 제공하는 프로젝트입니다. 1차 개발 중반에 합류해 2019년 10월 일부 기능을 먼저 출시했고, 2020년 3월 정식 출시했습니다. 이후 리뉴얼과 지속적인 기능 개발을 맡았습니다.

핵심 기능 담당: 학습지 만들기 · 교재 만들기

  • 사용자가 수학 콘텐츠를 직접 구성하는 "학습지 만들기"와 "교재 만들기" 기능 전체를 담당했습니다.

상태관리 일원화 (Redux + MobX → MobX)

  • 배경: Redux thunk와 MobX를 함께 쓰고 있어 서비스 복잡도가 매우 높았습니다.
  • 해결
    • 팀 논의를 거쳐 MobX로 통일하기로 했습니다.
    • Redux를 걷어냈습니다.
    • MobX를 편하게 쓰기 위한 util 함수와 스토어 생성자, 가이드를 만들어 제공했습니다.
  • 결과: 복잡도를 낮추고, 팀원들이 기능을 확장하기 쉬운 구조를 만들었습니다.

배포 전 E2E 테스트 자동화

  • 배경: 3주 단위 정기 배포마다 QA 일정과 여력이 부족했습니다. 미처 보지 못한 곳에서 에러가 나 CS로 들어오는 일이 잦았습니다.
  • 해결
    • Cypress E2E 테스트를 도입했습니다.
    • GitHub Actions로 배포할 때마다, 그리고 원할 때 언제든 실행되도록 했습니다.
    • 결과는 Slack으로 알림을 보냈습니다.

리뉴얼 및 구조 개선

  • 런칭 후 서비스 확장을 위해 리뉴얼을 진행하면서 구조를 다시 설계했습니다. 설계한 아키텍처는 팀원 5명에게 공유했습니다.
  • Storybook을 이용한 컴포넌트 기반 개발을 도입했습니다.
  • 안드로이드 앱 안에 일부 페이지가 웹뷰로 들어가면서, 환경별 분기처리 공통함수와 인증을 담당했습니다.
  • BE와 FE가 주고받는 데이터 포맷 규칙을 제안하고 적용했습니다. 이 포맷에 맞춘 API 인터셉터로 에러 로깅과 영향 범위를 쉽게 파악하게 했습니다.

iOS 대응: PWA

  • 배경: 안드로이드 앱만 있고 iOS 앱은 만들 수 없는 상황에서, iOS 지원 요청이 많아졌습니다.
  • 해결: PWA를 적용하고 사용 가이드를 제공해, iPad 사용자도 앱처럼 쓸 수 있게 했습니다.

프론트엔드 파트 리드 (2020.07 ~ 2022.10)

6명의 FE 개발자 중 가장 오래 재직했고 서비스 이해도가 높아 파트 리드를 맡았습니다. 개발 일정 논의에 참여하고, 팀의 생산성을 높이고 반복적인 일손을 줄이는 데 집중했습니다.

  • 자동화: Jira API·Jira Automation과 GitHub Actions로 티켓 상태와 일정 관리 같은 반복 업무를 자동화했습니다. 그 결과 팀의 작업 흐름을 한눈에 파악하기 쉬워졌습니다.
  • 문서화: 서비스 정책과 기능 개발 히스토리가 부족해서, 개발하면서 틈틈이 Notion에 정리하고 공유했습니다.
  • 지식 공유: 사내 지식 공유 자리인 Developer Talk를 만들어 운영했습니다. MobX Deep Dive, 2021년 회고 등을 발표했습니다.
  • 유지보수: 외주로 만든 Electron 앱의 버그를 고치며 유지보수했습니다.
